    Processing scope and source notes

    Cross-region inference and OCR/layout belong to the same capacity-expansion stage: both can use more eligible GPU capacity beyond one region. Data Zone limits processing to an eligible zone, such as US or EU; Global permits processing across the globe within the service's supported locations. These are processing choices, not separate HA tiers or a promise that a single request runs on multiple GPUs.

    The model and OCR controls still need to be configured for their supported operations. Foundry uses supported model deployment types; public CU guidance describes processingLocation for prebuilt-read and prebuilt-layout only. This page does not claim that every custom extraction analyzer can broaden its OCR scope, or that the stage-three invoice demo configures that option. Cross-region processing does not relocate the CU endpoint or its stored results.

    Grounding: Foundry model deployment types, CU processing locations and data handling, and How Traffic Manager DNS works. Check the current API, region, analyzer and model availability before deployment.
